# Project Memory

## Project
- Static portfolio site for Lucian Rodríguez Plasencia based on `Curriculum Lucian_1.pdf`.
- No existing web framework, package manager, or UI component system was present.
- Main entry point is `index.html`; styles and browser interactions live in `styles.css` and `script.js`.

## Design and implementation
- Spanish-language editorial portfolio with antique-ivory, piano-black, and surf-turquoise solid-color tokens; oversized bold Georgia display type and system sans-serif body.
- Responsive layouts use a single CSS file and fluid sizing; no gradients, external fonts, icon packs, or runtime dependencies.
- Hero parallax uses requestAnimationFrame and a small CSS transform; reveal effects use IntersectionObserver. Both respect `prefers-reduced-motion`.
- Mobile navigation is a native disclosure button with `aria-expanded`, Escape-to-close, and link activation to close.
- A scroll-driven ink-reveal interlude lives between the portfolio hero and recognition strip. It uses a desktop workflow SVG plus a portrait-specific SVG selected by `<picture>`, a custom Canvas 2D procedural ink edge on desktop, and CSS circular layers on coarse-pointer phones. Portrait mode disables background parallax scaling; wider portrait viewports contain the full illustration instead of cropping it. The surf-turquoise overlay and piano-black title appear together at the end of the reveal, and the final solid-turquoise state remains visible through the end of the scroll section. The replay control and its scroll handler were removed.
- The ink scene's effective scroll distance was shortened by 50% (from 465vh to 232.5vh); reveal thresholds, expansion timing, parallax, and the hidden geometry marker are scaled to preserve the same sequence and final turquoise/title state.
- Ink scene geometry is read from its in-page journey marker after image decoding and font readiness; no global fixed-scroll runtime or external assets are added.
- Search metadata includes Spanish description/title, Open Graph and Twitter summary fields, and Person JSON-LD. The decorative workflow SVGs remain vector; the primary image is lazy-loaded, asynchronously decoded, and low priority. No raster conversion or render-loop changes were justified by the roughly 4 KB asset sizes and existing requestAnimationFrame scheduling.
- Contact links show only generic email/WhatsApp actions; the public HTML and Person JSON-LD omit the actual addresses, which are decoded from Base64 only on deliberate click. This deters basic static scrapers but cannot prevent determined bots from reversing public client-side code. Per user request, the CV links and PDF were removed from the public build while the local PDF remains untouched.
- A read-only security review found no exploitable vulnerabilities in the static site. Cloudflare Pages response headers are configured in `_headers`; they remain unverified on the live host until deployment. Canonical URL, sitemap, and absolute social-preview image metadata need the final public domain.
- Cloudflare Pages deployment uses `node build.mjs` with `dist` as the output directory, and `wrangler.toml` serves only `./dist`. The allowlisted build excludes graph and workspace files, applies `_headers`, and generates canonical/OG URL metadata plus sitemap directives when an HTTPS `SITE_URL` is configured; without it, no placeholder domain is published. Security headers include CSP, HSTS, clickjacking/MIME/referrer protections, and least-privilege browser permissions; CSP allows inline styles because scroll effects update CSS properties at runtime. LinkedIn profile metadata uses the user-provided URL.
- Resume facts are sourced from the included two-page PDF. Use the PDF as the source of truth when updating career content.

## Privacy, services, and legal pages
- Added six CV-based digital service cards to `index.html`, with ES/EN/PT copy, a required terms/privacy checkbox, service-specific WhatsApp prefill messages, and a client-logo permission note. Every WhatsApp action is gated by the checkbox; the main contact CTA focuses the checkbox and announces why when it has not been accepted.
- Centralized WhatsApp number decoding/opening in `script.js`; card messages use `URLSearchParams`, and the number is not left in a page link after activation. The client-side checkbox is not persisted as proof and is described accurately in the UI and terms.
- Added `privacy.js` for ES/EN/PT translations, legal-page language selection, cookie preference handling, and Google Analytics 4. The portfolio resolves language in this order: valid `?lang=`, unexpired user preference, then Spanish; a fresh visit defaults to Spanish regardless of browser language. Manual and URL-selected languages are stored locally for 180 days. Translations update visible copy, metadata, legal links, service messages, and localized workflow artwork. Analytics is not embedded in HTML and loads only after opt-in or a valid stored opt-in. Rejection sets the GA opt-out flag, clears matching analytics cookies, and stores the preference for 180 days. GA cookies are configured for up to 180 days.
- Added trilingual `privacidad.html` and `terminos.html`. They describe the 12-month consultation retention policy, the 180-day local choice/cookie periods, external providers, third-party contact channels, written contracting, and the lack of online payment or stored consent proof. They clearly state that GA4's 14-month event/user retention must be configured and verified manually before enabling production analytics; the site cannot control the property setting.
- Added service cards, checkbox, legal-page, footer, and responsive cookie-banner styles in `styles.css`, including visible focus states and single-column mobile behavior.
- Updated `_headers` CSP to permit only the GA tag host and GA collection endpoints needed after opt-in. Removed the prior unconditional GTM snippet. Extended `build.mjs` allowlisting and canonical/OG URL and sitemap generation to include legal pages; `SITE_URL` remains required for production canonical URLs and sitemap.
- Verification: JavaScript syntax checks, public build, browser checks for analytics absent before consent, reject/accept persistence, translations, checkbox gating, service-specific message construction, legal language switching, and no horizontal overflow at 320px and 390px. IDE diagnostics reported no errors. A read-only security review found no exploitable vulnerabilities. Manual GA4 retention and final production `SITE_URL` remain deployment tasks; physical-device and formal legal review remain unverified.
- The header language control is a custom select-only combobox with inline SVG flags for Spain, the United States, and Brazil, a selected check state, a labelled listbox, and arrow/Home/End/Enter/Space/Escape/Tab keyboard behavior. Its trigger is borderless with a visible keyboard focus ring; it has no separate visible label, and each option retains a written language name and a 44px touch target.
- Multilingual verification: With browser preferences `en-US` and `es-ES`, no query parameter, and no saved choice, the page defaults to Spanish. Manual Portuguese and keyboard-selected English choices updated content and persisted across reloads; `?lang=pt` overrode the saved language on the Portuguese terms page. The selector and popup remain inside 320px and 390px viewports with 44px options and no horizontal overflow. The language preference's 180-day retention is disclosed in all three privacy-policy sections.
